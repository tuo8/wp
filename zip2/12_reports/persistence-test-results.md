# 删除后的持久化窗口实测

> 原始数据：`08_persistence_tests/delete_persist.json`（2026-11-23 01:20:35 起 8 分 15 秒）
> 脚本：`11_scripts/t24_delete_persist.py`

## 1. 做法

1. 对目录 `hca-2026-11-23` 内的 3 个对象发 `PubUserFile/Delete`（`source = File{identity} ×3`）。
2. **删除前**先为其中一个对象（10 MiB）取一张 7 200 s 有效的直连预签名 URL。
3. 删除后在第 0、10、70、190、490 秒各做三件事：
   - 重新 `List` 该目录；
   - 用**删除前**那张预签名 URL 再取一次整文件（比对 SHA-256）；
   - 用被删对象的根 CID 重新申请 `GetSliceDownloadAddress` 并真的取一次根块。

## 2. 结果

| 时间点 | List 中是否还有被删对象 | 预签名 URL | 预签名 URL 的 `age` | `via` | 根块重新取址 |
|---|---|---|---|---|---|
| t+0 s | 否（元数据立即消失） | 200，10 485 760 B，SHA-256 一致 | 0 | `cache33.czmp,cache04.hetangshan-cu78` | 成功，165 B |
| t+10 s | 否 | 200，SHA-256 一致 | 12 | `cache04.hetangshan-cu78` | 成功，165 B |
| t+70 s | 否 | 200，SHA-256 一致 | 73 | `cache04.hetangshan-cu78` | 成功，165 B |
| t+190 s | 否 | 200，SHA-256 一致 | 194 | `cache12.hetangshan-cu78` | 成功，165 B |
| t+490 s | 否 | 200，SHA-256 一致 | 495 | `cache06.hetangshan-cu78` | 成功，165 B |

（`Delete` 本身：HTTP 200，响应为 `{"1":"lock__user_operation__f42c4f7a…","2":1000,"3":3,…}`，即一个操作锁标识，无错误。）

## 3. 怎么解读

**能确定的（CONFIRMED）**

1. **元数据删除是立即且持久的**：5 个时间点 `List` 都不再返回被删对象，8 分钟内没有「复活」。
2. **数据块在删除后 ≥490 s 仍可按块读取**：不仅是 CDN 缓存里的整文件（预签名 URL），连按根 CID 重新申请的**新**分片地址也能取到块（说明源站对象还在，不只是边缘缓存）。
3. **CDN 缓存确实存在两级**：`age` 从 0 递增到 495 而内容不变，且 `via` 从两跳（`cache33.czmp,cache04.hetangshan-cu78`）变为单跳（`cache04…`）再切到 `cache12`/`cache06`，说明命中层级在变、源站未变。

**不能确定的（UNKNOWN）**

- 数据块最终何时被物理回收：只测到 490 s，未继续拉长；也不能通过接口查询回收策略。
- 「490 s 后可读」是「延迟删除 + 定期 GC」还是「软删除保留期」，无法从客户端侧区分。

**必须避免的过度解读**

- 这**不等于**「删除无效」或「数据永久保留」。它只证明**删除不是同步物理擦除**，存在一个至少 8 分钟的可读窗口。
- 预签名 URL 的有效期（7 200 s）本身也会让链接在删除后仍可用，因此「URL 还能下」单凭 URL 本身不足以证明源站未删；本条结论主要依赖**按 CID 重新取块成功**这一独立证据。

## 4. 观测到的异常（如实记录）

- t+0 至 t+190 的 `List` 只返回了 1 个对象（`hca-kb1-full.bin`），t+490 的 `List` 返回了 3 个（多出 `hca-up-mb50.bin`、`CAWD-987-AI.mp4`），而这两个对象**从未被本次删除命中**。
- 一种解释是删除操作期间的操作锁（响应里的 `lock__user_operation__…`）导致列表短暂不完整、随后恢复；另一种是客户端同步引擎在那几分钟内重传了 `hca-up-mb50.bin`。
- **无法区分**，标注 `UNKNOWN`。影响面：这不影响「被删的 3 个对象没有复活」这一结论（三者在 t+490 仍未出现），但说明该接口的列表在并发操作下可能最终一致。

## 5. 复现

python 11_scripts/t24_delete_persist.py   # 会真实删除 3 个测试对象（仅测试目录内自建对象）
